# AI Agent: Anatomy of OpenClaw as an Example by Hung-Yi Lee

## Resources

- https://www.youtube.com/watch?v=2rcJdFuNbZQ

## Content

- How OpenClaw interacts with user
  - Via message APP: Line, WhatApp, Discord
- AI Agent
  - Auto-GPT (2023)
  - Claude Code (2025)
  - Gemini CLI (2025)
- AI Agent IS NOT LLM, AI Agent is interface between human and LLM
  - It contains
    - Memory system
    - Task Management system
    - Computer usage
- Imagination for AI Agent
  - Facebook for clawbots: https://www.moltbook.com/
  - Request for Human physical help from clawbots: https://rentahuman.ai/
- Context engineering:
  - LLM is stateless, that is, for every single interaction with agent, the entire history is sent back to the LLM
- System Prompt (usually takes more than thousands of tokens)
  - Dive-in:
    - Identity
      - SOUL.md
      - IDENTITY.md
      - USER.md
      - MEMORY.md:
        - Long-term memroy
    - Tools: e.g., Read (for reading files on computer)
    - SKILL
    - Behavior:
      - AGENTS.md
    - History Memory
    - etc.
  - They are just text files can be modified by both human and AI Agent
- How AI agent uses your computer?
  1. User queries OpenClaw
  2. OpenClaw queries LLM
  3. LLM sends back tool calling response w/ context starts w/ `[tool_use]`
  4. OpenClaw executes the pre-defined tool (commands) on computer
     - What tools are for and How to use tools are all pre-defined
       - e.g., Shell command can be run by OpenClaw with `exec`
- Potential Attack and How to Defense
  - Attack
    - Trigger OpenClaw to run some malicious shell command like `rm -rf` via `exec`
  - Defense
    - LLM-Level defense
      - `MEMORY.md`: Restrict what LLM can do in system prompt
    - OpenClaw-Level defense
      - Config file: Ask human approval for all `exec` commands
- Sub-agent (`sessions_spawn`)
  - Spawn new agents for tasks to keep context window of original agent clean
    - For task: web search, page summarization, etc.
  - Caveat:
    - Description: If sub-agent can call sub-agent for itself too, then it can become an endless loop
    - Solution: In OpenClaw level, remove the spawn ability from sub-agent
- `SKILL.md` (Task SOP)
  - Text files to record SOP for specific tasks
  - In system prompt, SKILL file paths are found and added for context engineering
    - Just put SKILL.md to the right places and everything works.
    - Clawhub: https://clawhub.ai/
- Memory in OpenClaw
  - Short-term memroy
    - Context in chat session is kept as short-term memory
  - Long-term memory
    1. Write memory as text file (`MEMORY.md`) for long-term memory
    2. Search memory (call back)
       - Use RAG with memory file by comparing the similarity
- NOTE: DO NOT just listen to what agents say, check what agents do instead
  - Always remember to check if the agents really do what they say
- `HEARTBEAT.md` (Refresh session by asking LLM to check if there are anything to do)
  - e.g., Check news every fifteen minutes
- Cron Job for OpenClaw (The Wait compatibility by adding a timer to add task to HEARTBEAT)
  - Make agent learn to wait for other tool completing their jobs
    - e.g., If the video is generating, check again after three minutes
- Context Compression
  - Compaction
    - When reaching content window limit, Call `Compaction` to summarize previous contexts
    - NOTE: only chat context is summarized, system prompt is still be called at the very beginning of context
  - Pruning
    - Soft Trim
      - Keep only beginning and end of Tool output
    - Hard Clear
      - Remove entire tool output but record that tool is called
- How to prevent mistakes? We all could make mistakes, so just make the possible mistakes not that devastating
  - Create a safe environment for AI Agent, follows following rules
    - Remember to add Security Guideline to them
    - Check what they do
    - Separate account from daily usage (give them their own Gmail, GitHub)
    - Put them on an brand-new (or formatted) computer
