## 1/3 Context Engineering

- Memory Compression
  - Method
    - LLM-Summary: Summarize context to shorten context
    - Hard Clear (Observation Masking): Remove Tool output in context and add `There was a Tool output`
      - Pros: Reduce cost (token consumption) comparing to raw context
      - Caveat:
        - Sometimes compression not always gets better result due to trajectory elongation
          - Since some Tool output are removed, LLM re-runs the Tool outputs, which makes the total steps increase
    - Log file: Save Tool output to a text file `log.txt` and replace the Tool output to file path instead
      - When the LLM needs to find out the Tool output, it opens the text file
- Context vs Prompt
  - Context consists in two part P (Prompt) vs M (Non-prompt)
    - P: Information actually sent to LLM (e.g., log file path)
    - M: Information stored externally (e.g., log content)
- Context Collapse
  - Description: When the information losses during context summarization by LLMs
  - Solution: Agent Context Optimization (ACON)
    - Note: There is no fine-tuning process in ACON
    - Steps
      1. Use another LLM to critic (generate feedback for) context collapse cases
      2. Feed feedback to LLM that are going to summarize
  - Solution: SUmmarization augmented Policy Optimization (SUPO)
    - This helps LLM learns how to summarize and how to read summarize better
    - Steps
      1. Reinforce Learning with reward on the output of task with LLM-summary
- When to do Memory Compression?
  - LLM doesn't like to compress memory
  - AgentFold
    - Prompt cannot stably make LLM use compression tool
    - LLM needs to be fine-tuned to learn to use compression tool
  - Subagent
    - Can be viewed as some kind of compression by itself
      - Context from subagent is dropped once subagent returns brief result to main agent
    - Use RL training to train LLM to call sub-agent
      - Add punishment for
        - Main agent: for too long context length
        - Sub agent: for doing tasks out of assignment
- Context blot: Most of context for complex problem solving is observation (~85% in context)
  - Filtering: `memory_get` function in OpenClaw
    - Just make the observation focus on things that really related and filter out unnecessary content
      - e.g., When reading a log, just open from line N1 to line N2 instead of the whole log files
  - Filtering: MCP-Zero
    - Dynamic Tool Loading: Load tool only when LLM actually needs them
      - Let LLM generate description of the required tool to search engine
        - e.g., `I need ...`
- Agentic Context Engineering
  - Let LLM decide what to do for context
    - It still needs some prompt engineering to make LLM learn how to manipulate contexts
  - Let LLM update itself to learn strategies when doing context engineering
    - e.g., Save things that can be re-used in the future
  - Approaches
    - Agentic Context Engineering
      - Playbook: context to store spirits/strategies for context engineering
      - Playbook updating 3-agent pipeline
        1. LLM generator
        2. LLM reflector
        3. LLM curator
    - Recursive Language Models
      - Let LLM manage its own metadata data and use tool (maybe write a small code ) to search it own long-term memory
      - Make LLM easily handle extremely long context

      - Mesh
      - Layer (like Neural Network)
      - Random (randomly pruning from Mesh)

    - Accuracy improves as the number of agents increase, but eventually saturates
